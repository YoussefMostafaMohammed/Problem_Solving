## **إيه هو الـ Greedy بالظبط؟**

الجريدي الجورزم (Greedy Algorithm) هو طريقة تفكير قائمة على **الحدس البسيط**:  
> **"لو خدت أفضل خطوة في كل مرة، هتوصل للإجابة الأمثل في النهاية."**

يعني بدل ما تقعد تفكر في 100 خطوة جاية، أنت بس بتسأل نفسك: **"إيه أفضل حاجة أعملها دلوقتي؟"**  
وتاخدها على طول من غير ما تفكر في أثرها على المستقبل.

مثال بسيط: لو معاك 6 طرق توديك من القاهرة للإسكندرية، والـ brute force هيجرب الـ 6 طرق ويقارن بينهم، أما الـ greedy هيسأل: **"من بين الطرق المتاحة دلوقتي، إيه أقصر طريق؟"** وياخدها ويمشي.

---

## **الفرق بين Brute Force و Greedy**

### ال **Brute Force (القوة العمياء)**
أنت بتجرب **كل الاحتمالات** وفي الآخر تختار أفضل واحد فيهم.  
**عيوبه:** الـ time بيكون **exponential** (O(2^N) أو أسوأ) والكمبيوتر هيتعب أوى.

### ال **Greedy (الطمع)**
أنت بتختار **أفضل خيار محلي** في كل خطوة وتفتكر إنه هيوصلك للحل الأمثل.  
**مميزاته:** سريع جداً (O(N log N) في أغلب الحالات) وبسيط في التطبيق.
    
**المفتاح:** الجريدي مش بيعمل "backtracking" - يعني لو أخد قرار، مش بيرجع فيه تاني.

---
## **متى نستخدم Greedy؟**

مش كل المسائل تتحل بـ Greedy! فيه شروط لازم تتحقق:

1. **المسألة ليها "اختيار محلي" واضح:** زي "أقل وقت" أو "أكبر قيمة".
2. **الـ constraints كبيرة:** لو N كبير (مثلا 10^5 أو أكتر)، الـ brute force مستحيل يشتغل.
3. **مفيش حل واضح غيره:** لما تكون المسألة "optimization" ومحتاج تقلل أو تزود حاجة.

**ملاحظة مهمة:** الجريدي مش بيشتغل في كل المسائل. زي **TSP (Traveling Salesman Problem)** - مشكلة التاجر اللي بيزور مدن - **مش** مناسبة للـ Greedy لأن الخطوة المحلى الأمثل ممكن تضيع حل كامل. في TSP، أنت محتاج تجرب كل الطرق (أو تستخدم تقنيات تانية زي dynamic programming).

## **أمثلة عملية على Greedy**

### **المثال الأول: أكبر عدد من التاسكات في وقت محدد**

**المسألة:** معاك N tasks، كل واحد فيهم ليه وقت محدد. ومعاك M دقائقة. عايز تعرف أكبر عدد تاسكات تقدر تخلصهم.

**الحل الـ Greedy:** **خد أقل تاسك في الوقت أول حاجة.** ليه؟ علشان كل ما تاخد تاسك صغير، بيسمحلك تاخد تاسكات أكتر بعده.

**الكود:**
```c++
#include <iostream>
#include <vector>
#include <algorithm>

int maxTasks(std::vector<int> times, int m) {
    std::sort(times.begin(), times.end()); // N log N
    
    int total = 0, count = 0;
    for (int t : times) {
        if (total + t <= m) {
            total += t;
            count++;
        } else break;
    }
    return count;
}

int main() {
    std::vector<int> times = {3, 10, 7, 12, 2};
    int m = 13;
    std::cout << "Max tasks = " << maxTasks(times, m) << "\n";
}
```

**Time Complexity:** O(N log N) بسبب الـ sorting  
**Space Complexity:** O(1)

**مثال من Codeforces:** [Gym Problem 102951B](https://codeforces.com/problemset/gymProblem/102951B)  
الحل هو نفس الفكرة بالظبط: sort و accumulate.

### **المثال الثاني: Coin Change – أقل عدد من العملات**

**المسألة:** عندك فئات عملات، وعايز تجيب مبلغ X بأقل عدد عملات.

**الحل الـ Greedy:** **خد أكبر عملة أقل من أو تساوي المبلغ المتبقي** في كل مرة.

**مثال عملي:**
```
Coins = [1, 2, 5, 10, 20, 50, 100, 200]
X = 411

الخطوات:
1. خد 200 → الباقي = 211
2. خد 200 → الباقي = 11
3. خد 10 → الباقي = 1
4. خد 1 → الباقي = 0

العدد = 4 عملات
```

**الكود:**
```c++
#include <bits/stdc++.h>
using namespace std;

int main() {
    vector<int> coins = {1, 5, 10, 20, 50, 100, 200};
    int X = 411;
    
    sort(coins.rbegin(), coins.rend()); // ترتيب تنازلي
    
    int count = 0;
    vector<int> used;
    
    for (int c : coins) {
        while (X >= c) {
            X -= c;
            count++;
            used.push_back(c);
        }
    }
    
    cout << "Minimum coins = " << count << "\n";
    cout << "Coins used: ";
    for (int c : used) cout << c << " ";
}
```

**ملاحظة مهمة:** الجريدي في Coin Change **بيشتغل 100%** لما تكون الفئات "canonical" (زي النظام المصري أو الأمريكي). لكن في بعض الفئات الغريبة، ممكن يفشل!

### **المثال الثالث: Activity Selection – تختار أكبر عدد من الفعاليات**

**المسألة:** عندك tasks كل واحد ليه وقت بداية ونهاية. عايز تختار أكبر عدد منهم من غير ما يتداخلوا.

**الحل الـ Greedy:** **خد التاسك اللي بيخلص أول حاجة.** ليه؟ علشان كل ما التاسك يخلص بدري، بيسيبلك وقت أكتر للتاسكات اللي بعده.

**مثال:**
```
Task   Start   End
A       1       4
B       3       5
C       0       6
D       5       7
E       8       9
F       5       9

الحل الأمثل: A, D, E (أو C, D, E) → 3 tasks
```

**الكود:**
```c++
#include <bits/stdc++.h>
using namespace std;

struct Task {
    int start, end;
};

int main() {
    int N; cin >> N;
    vector<Task> tasks(N);
    for (int i = 0; i < N; i++) cin >> tasks[i].start >> tasks[i].end;
    
    // 1. ترتيب حسب وقت النهاية
    sort(tasks.begin(), tasks.end(), 
        [](const Task &a, const Task &b) { return a.end < b.end; });
    
    int count = 0, lastEnd = -1;
    
    // 2. اختيار الفعاليات
    for (auto &t : tasks) {
        if (t.start >= lastEnd) {
            count++;
            lastEnd = t.end;
        }
    }
    
    cout << count << endl;
}
```

**الدليل الرياضي:** في كتاب CLRS مثبت إن اختيار "أقرب وقت انتهاء" هو الأمثل 100%.

### **المثال الرابع: Elevator Rides – ركوب المصاعد**



**المسألة (CSES:** [1090 Ferris Wheel](https://cses.fi/problemset/task/1090) ):** عندك N طفل، كل واحد وزنه معروف. المصعد يتحمل وزن X. عايز تعرف أقل عدد رحلات للمصعد.

**الحل الـ Greedy:** **أثقل واحد مع أخف واحد.**  
- خد أثقل طفل لوحده  
- جرب تضيفله أخف طفل لو المصعد شالهم  
- لو لا، خليه يروح لوحده

**الكود:**
```c++
#include <bits/stdc++.h>
using namespace std;

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);
    
    int n; long long x;
    cin >> n >> x;
    
    vector<long long> weights(n);
    for (int i = 0; i < n; i++) cin >> weights[i];
    
    sort(weights.begin(), weights.end());
    
    int i = 0, j = n - 1;
    int gondolas = 0;
    
    while (i <= j) {
        if (weights[i] + weights[j] <= x) {
            i++; // الاثنين نزلوا مع بعض
        }
        j--; // الطفل الثقيل نزل لوحده
        gondolas++;
    }
    
    cout << gondolas << "\n";
}
```

## **الأفكار المشتركة في كل الحلول**

لاحظ إن كل الحلول الجريدي بيتبعوا نفس الطريقة:

1. ال **Sort (ترتيب):** دايمًا الخطوة الأولى - ترتيب البيانات (تصاعدي أو تنازلي)
2. ال **Scan (مسح):** تشغل على البيانات مرة واحدة من الأول للآخر
3. ال **Condition (شرط):** في كل خطوة، تختار العنصر اللي بيحقق شرط معين
4. ال **Update (تحديث):** تعدل المتغيرات بتاعتك وتكمل

**الزمن الكلي:** دايمًا O(N log N) بسبب الـ sorting  
**المكان:** O(1) أو O(N) لو حفظت البيانات

## **إزاي نثبت صحة الحل؟ (Proving by AC)**

المفترض إنك لما تيجي تحل مسألة Greedy تقدم مع حلك mathematical proof، بس **احنا مش بنعمل كدة** في المسابقات!

الطريقة العملية هي:
1. **فكر في الحل الجريدي** (sort + خد أفضل حاجة)
2. **جرب test cases صغيرة** تتأكد من الفكرة
3. **حاول تلاقي counter-example:** لو لقيت مثال واحد يخلي الحل يفشل → الحل غلط
4. **لو ملقيتش counter-example → اعمل submit!**
5. **لو جاب Accepted → الحل صحيح** (Proving by AC)

**لماذا دا شائع؟**
- الوقت في المسابقات محدود
- ال Judge system هو البرهان النهائي
- لو الحل فعلاً غلط، هتلاقي test case يكسره

## **خلاصة ونصائح نهائية**

### **متى تستخدم Greedy؟**
✅ المسألة طالبة **تقليل** أو **زيادة** حاجة معينة  
✅ فيه **خيار واضح** في كل خطوة (أقل، أكبر، أقرب)  
✅ الـ **constraints** كبيرة (N > 10^4)  
✅ المسألة من **الأنماط المعروفة**

### **متى لا تستخدم Greedy؟**
❌ المسألة طالبة **أمثلية مطلقة** بس فيه تداخلات معقدة  
❌ فيه **counter-example** واضح في دماغك  
❌ المسألة **معروفة** إنها تحتاج DP أو backtracking
